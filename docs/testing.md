# 测试说明

## 测试层次

| 检查 | 入口 | 验证内容 |
| --- | --- | --- |
| 语法 | `npm run check` | 运行时代码、启动脚本和宿主测试的 JavaScript 语法 |
| 单元 | `npm test` | 解码、分页、章节、搜索、书架、书签、布局计算与边界校验 |
| Extension Host | `npm run test:integration` | 真实命令调用、编辑器、隐藏竞争、批量导入与原生树数据 |
| 持久化 | `npm run test:persistence` | 两个普通开发宿主之间的恢复及 SQLite 落盘检查 |
| 包内容 | `npm run package:contents` | VSIX 文件白名单，无测试、脚本、缓存或私有资料 |
| 本地安装 | `npm run package` 后安装 VSIX | 产物可安装，扩展入口与 UI 命令正常 |

`npm run verify` 包含语法与单元测试。集成测试不直接交给 Node.js 的单元测试发现器执行，而由 VS Code 加载。

## 宿主环境

macOS 默认使用 `/Applications/Visual Studio Code.app/Contents/MacOS/Code`。其他环境由 `@vscode/test-electron` 下载 VS Code，或通过 `VSCODE_EXECUTABLE_PATH` 指定已有可执行文件。宿主测试需要图形桌面；无显示环境需要维护者另行配置虚拟显示。

测试使用临时用户数据与扩展目录，不读取或修改日常书架。核心自动测试关闭临时配置中的失焦隐藏，以避免其他桌面应用的焦点干扰。正常退出后清理临时目录；中断后应检查本任务创建的宿主进程是否已退出，不能结束用户其他 VS Code 窗口。

部分 VS Code 测试模式可能使用内存全局存储，因此跨进程测试通过独立驱动扩展启动两次普通开发宿主，不用单个测试进程替代重启验证。

## 发布前手动检查

在隔离配置中准备可公开的小段示例文本：

1. 单书导入与批量导入，确认成功、重复、空文件、缺失文件等情况。
2. 三种阅读模式的翻页、恢复、章节、搜索、书签和百分比跳转。
3. 在随行阅读期间编辑并保存代码，确认原书正文没有写入源码。
4. 将随行行数改为 12，检查短文件、窗口底部及滚动；还原测试配置。
5. 从图形界面改名、取消移除、确认移除，确认原文件保留。
6. 测试立即隐藏、失焦隐藏、返回后的手动恢复以及重启后默认隐藏。
7. 关闭测试宿主并确认清理；保留预览窗口需得到使用者明确要求。

## 尚未覆盖

Windows/Linux 实机、VS Code 1.85 最低支持版本、Remote/WSL、完整辅助技术流程和长时间大书架压力测试尚未验证。章节识别、超长代码行对齐及多窗口同时写书架的限制见[使用指南](user-guide.md)。自动测试通过不能替代这些场景的验收。
